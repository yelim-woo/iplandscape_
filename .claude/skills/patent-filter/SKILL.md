# patent-filter — 유효특허 데이터 필터링

특허 raw 데이터 폴더(.xlsx 여러 개 가능)를 받아, 2단계 필터링으로 유효 데이터만 남긴다.
**유효특허 선정기준은 파일로 받거나, 없으면 Claude가 초안을 만들어 사용자 승인 후 사용**하므로
사용자가 기준 문서를 직접 작성하지 않아도 된다. 결과는 patent-trend / patent-quality 에 바로 투입 가능하다.

```
입력: <raw폴더>(xlsx들)  [+ 선정기준.txt (선택)]
  └─ 1차 (기계적·결정적, Python)   : 법적상태=등록 + 출원일 최근 N년
  └─ 선정기준 확보                  : 파일로 받거나 / 연구주제+샘플로 Claude 초안 → 사용자 승인
  └─ 2차 (의미 판단, Claude LLM)    : 선정기준 기반 관련성 판정
출력: <raw폴더>/유효데이터.xlsx + <raw폴더>/제외로그.xlsx + <raw폴더>/선정기준.txt
```

## 경로
- 스크립트: `${CLAUDE_SKILL_DIR}/scripts/_filter_stage1.py`, `${CLAUDE_SKILL_DIR}/scripts/_profile_for_criteria.py`, `${CLAUDE_SKILL_DIR}/scripts/_apply_verdicts.py`
- 중간 산출물: `<raw폴더>/_filter/`
- 최종 출력: `<raw폴더>/유효데이터.xlsx`, `<raw폴더>/제외로그.xlsx`

## 사전 조건
- raw 폴더에 `.xlsx` 1개 이상 (WIPS·KIPRIS·USPTO·Espacenet·Lens 등 어떤 DB든. 컬럼 자동매핑 내장)
- **강건 리더 내장**: KIPRIS 익스포트의 손상된 스타일시트(openpyxl 오류)는 `calamine` 엔진으로 자동 폴백하고, 상단 제목/검색식 블록 때문에 헤더가 0행이 아니면 **헤더 행을 자동 탐지**한다(`python-calamine` 자동 설치). KIPRIS xlsx도 그대로 입력 가능.
- Python 패키지: `pandas`, `openpyxl`
- 선정기준 텍스트 파일은 **선택**이다. 없으면 Stage 2에서 자동 생성한다 — 사용자에게 파일을 요구하지 말고,
  대신 "무엇을 분석하는지" 연구주제/분석목적을 한 줄 물어보면 된다.

## 작업 흐름 (3단계)

### Stage 1 — 1차 필터링 (법적상태 + 출원일)

먼저 raw 엑셀 하나를 Read 해서 컬럼 헤더를 확인한다. WIPS 표준 컬럼(`출원일`, `법적상태`/`상태정보[...]`,
`발명의 명칭`, `요약` 등)이면 바로 실행한다. 비표준이라 자동매핑이 안 될 듯하면 `column_map.json` 을 작성한다.

`column_map.json` 형식 — `{원본컬럼명: 역할}`, 역할은 다음 중 하나:
`출원일`, `법적상태`, `발명의명칭`, `요약`, `청구항`, `출원번호`, `ipc`
```json
{ "Filing Date": "출원일", "Legal Status": "법적상태", "Title": "발명의명칭", "Abstract": "요약" }
```

실행 (기준일은 오늘, 최근 10년이 기본):
```bash
python "${CLAUDE_SKILL_DIR}/scripts/_filter_stage1.py" "<raw폴더>" --asof <오늘 YYYY-MM-DD> --years 10
```
비표준 데이터면 `--column-map column_map.json` 추가.

**1차 판정 규칙** (스크립트 내장):
- **법적상태**: `등록`(granted/registered/active 포함)인 행만 통과. 단 `등록취소·무효·소멸·거절·포기·취하` 등
  부정 상태가 섞여 있으면 제외. → 즉 "현재 등록(유효)" 권리만 남김.
  - **판정 보류(공란) 예외**: 법적상태 값이 **통째로 비어 있어 등록 여부를 판정할 근거 자체가 없는 행**
    (KIPRIS 해외검색 결과처럼 법적상태·등록번호·등록일을 아예 제공하지 않는 국가 데이터)은
    "비등록"으로 **제외하지 않고 통과**시켜 2차 의미판정으로 넘긴다. 이렇게 하지 않으면 등록 기준이
    법적상태 미제공 해외건(CN·US·JP·EP 등)을 **전량 탈락**시켜 분석에서 사라진다. 보류 통과 건수는
    로그와 `_meta.json`의 `status_blank_held`에 남는다. (명시적 비등록 상태가 적힌 행은 종전대로 제외.)
- **출원일**: `기준일 − N년` 이후 출원만 통과 (기본: 오늘 기준 10년 → 2016 이후). 출원일을 못 읽는 행은
  `출원일 불명` 으로 제외하되 로그에 남겨 사용자가 확인할 수 있게 한다.

산출물 (`<raw폴더>/_filter/`): `stage1_pass.xlsx`, `stage1_excluded.xlsx`, `stage1_pass.json`(2차용), `_meta.json`.
`_meta.json` 을 Read 해서 컬럼 매핑이 의도대로 됐는지, 통과 건수가 합리적인지 확인하고 사용자에게 한 줄로 보고한다.
법적상태/출원일 컬럼이 `null` 로 매핑됐으면 필터가 건너뛰어진 것이므로 column_map 으로 다시 실행한다.

### Stage 2 — 선정기준 확보 (파일이 없으면 Claude가 생성)

2차 판정의 근거가 될 **선정기준**을 확보하는 단계다. 두 갈래다.

**(A) 선정기준 파일을 받은 경우** — 그 파일을 Read 하고 바로 Stage 3 으로 간다.

**(B) 선정기준 파일이 없는 경우 — Claude가 초안을 만들고 사용자 승인을 받는다.**
사용자에게 기준 문서를 써오라고 요구하지 않는다. 대신:

1. **연구주제/분석목적을 한 줄 묻는다.** (예: "이번 분석은 무엇에 대한 건가요? 한 줄이면 됩니다 — 예: '수술용 로봇의 동력전달 기술'") 이미 대화에 주제가 있으면 다시 묻지 않는다.
2. **데이터를 프로파일링**해 기술 범위를 파악한다 (1차 통과본을 표본으로):
   ```bash
   python "${CLAUDE_SKILL_DIR}/scripts/_profile_for_criteria.py" "<raw폴더>" --n 40
   ```
   `<raw폴더>/_filter/data_profile.json` 을 Read — `total`, `ipc_top`(IPC 분포), `samples`(IPC별 고르게 뽑은 대표 명칭·요약)가 들어있다.
3. 연구주제와 데이터 프로파일을 함께 보고 **선정기준 초안**을 작성한다. 반드시 **포함 조건 / 제외 조건**을 구체적 기술 표현으로 적는다 (데이터에서 실제로 보이는 인접·노이즈 기술을 제외 조건에 명시하면 2차 판정이 정확해진다):
   ```
   [분석 대상] 수술용 로봇의 동력전달 기술
   [포함 조건]
   - 로봇/매니퓰레이터의 관절·구동·동력전달(샤프트, 기어, 토크 전달 등)을 핵심 구성으로 하는 특허
   - 수술/내시경 로봇의 구동 메커니즘
   [제외 조건]
   - 로봇과 무관한 일반 기계 동력전달(자동차 변속기 등)
   - 영상처리·진단 알고리즘만 다루고 동력전달 구성이 없는 특허
   - 단순 센서/소재 특허
   ```
4. 초안을 사용자에게 보여주고 **승인 또는 수정**을 받는다. 선정기준이 전체 필터링 결과를 좌우하므로 이 확인은 생략하지 않는다. 사용자가 수정 사항을 주면 반영한다.
5. 확정된 기준을 `<raw폴더>/선정기준.txt` 로 Write 해 보관한다(재현·기록용). 이 파일이 이후 Stage 3의 입력이 된다.

### Stage 3 — 2차 필터링 (선정기준 의미 판단, Claude 가 수행)

이 단계는 스크립트가 아니라 **Claude 본인이 판단**한다. 1차에서 살아남은 특허 각각이
선정기준에 부합하는지를 제목·요약·청구항을 읽고 판정한다.

1. Stage 2에서 확보한 선정기준의 **포함 조건 / 제외 조건**을 기준으로 삼는다.
2. `<raw폴더>/_filter/stage1_pass.json` 을 Read 한다. 각 레코드는 `{uid, 출원번호, 명칭, 요약, ipc, 청구항}`.
3. 각 특허마다 선정기준에 비춰 **유효(valid=true) / 비유효(valid=false)** 와 **간결한 사유**를 판정한다.
   - 기준은 발명의 실질 내용으로 본다. 명칭만으로 애매하면 요약·청구항을 근거로 삼는다.
   - 경계선·불확실한 경우의 처리 방침은 선정기준을 따른다. 기준에 없으면, 노이즈 제거가 목적이므로
     "기준 기술이 발명의 핵심인가"를 잣대로 판단하고 사유에 근거를 적는다.
4. 결과를 `<raw폴더>/_filter/stage2_verdicts.json` 으로 Write 한다:
```json
[
  {"uid": 1, "valid": true,  "reason": "X 기술을 핵심 구성으로 청구 — 기준 부합"},
  {"uid": 2, "valid": false, "reason": "단순 Y 장치, 기준 기술 미포함"}
]
```
**모든 uid 를 빠짐없이** 판정한다(누락 시 미판정으로 제외 처리됨).

**대량 데이터 처리**: 1차 통과 건수가 많으면(대략 150건 이상) 한 번에 다 읽기보다 **나눠서** 판정한다.
- 직접 처리: stage1_pass.json 을 20~30건씩 끊어 읽고 판정해 verdicts 를 누적 Write.
- 더 빠르게: 사용자가 워크플로우 사용에 동의하면, 배치별로 판정 에이전트를 병렬로 띄우고 결과를 합쳐
  stage2_verdicts.json 으로 저장한다(각 에이전트에 선정기준 전문 + 담당 배치를 전달, 스키마로 구조화 출력).

### Stage 4 — 결과 조립 (유효데이터 + 제외로그)

```bash
python "${CLAUDE_SKILL_DIR}/scripts/_apply_verdicts.py" "<raw폴더>"
```
- `유효데이터.xlsx` — 1차·2차 모두 통과. **원본 컬럼 그대로** 보존(보조컬럼 `_uid` 제거).
  - **컬럼 통합(국내/해외 스키마 정합)**: KIPRIS 국내+해외 익스포트처럼 같은 개념이 이름만 갈라진
    경우(`발명의명칭`↔`발명의 명칭`, `IPC분류`↔`IPC` 등)를 대표 컬럼으로 병합해, 해외행의
    명칭·IPC가 다른 컬럼에 남아 **정량(IPC 분포)·정성(등고선·기술흐름) 차트에서 누락되는 것을 방지**한다.
    국가가 비고 출원번호가 숫자만이면 `KR`로 보정. 병합 내역은 로그에 남는다(`unify_columns`).
- `제외로그.xlsx` — 1차 제외 + 2차 제외 통합. `제외단계`(1차/2차) + `제외사유` 컬럼 포함.

## 실행 순서 요약
```
1. raw 엑셀 1개 Read → 컬럼 확인 → (필요시) column_map.json 작성
2. python scripts/_filter_stage1.py <raw폴더> --asof <오늘> --years 10 [--column-map ...]
3. _filter/_meta.json Read → 매핑·통과건수 확인, 사용자 보고
4. 선정기준 확보:
   - 파일을 받았으면 그 파일 Read
   - 없으면: 연구주제 한 줄 질문 → python scripts/_profile_for_criteria.py <raw폴더>
     → data_profile.json Read → 선정기준 초안 작성 → 사용자 승인 → <raw폴더>/선정기준.txt Write
5. stage1_pass.json Read → 선정기준대로 각 uid 판정 → stage2_verdicts.json Write
   (건수 많으면 배치/워크플로우로 분할 판정)
6. python scripts/_apply_verdicts.py <raw폴더>
7. 유효데이터.xlsx / 제외로그.xlsx 경로 + 단계별 건수(총→1차→2차) 안내,
   "patent-trend / patent-quality 로 바로 분석 가능"을 덧붙인다
```

## 주의사항
- **원본 보존**: 유효데이터는 원본 컬럼 구조를 유지해 다운스트림 스킬과 호환된다. raw 파일은 수정하지 않는다.
- **투명성**: 모든 제외 건은 제외로그에 사유와 함께 남긴다. 조용히 버리지 않는다. 1차에서 컬럼 미탐지로
  필터가 통째로 건너뛰어진 경우 반드시 사용자에게 알린다.
- **기준 변경**: 법적상태/출원일 범위가 선정기준 텍스트에 따로 명시돼 있으면 그쪽을 우선해 `--years`,
  `--asof` 또는 column_map 을 조정한다.
- **재현성**: 중간 산출물(`_filter/`)이 남으므로, 2차 기준만 바꿔 Stage 2~3 만 다시 돌릴 수 있다.
- `taskkill`/강제 프로세스 종료 사용 금지.
